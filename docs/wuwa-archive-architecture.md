# Wuthering Waves Archive Architecture Notes

This document records the current WuWa PC archive design before the same
workflow is adapted to other games. It focuses on the parts that protected the
site during the TomyJan historical import: staging first, formal promotion in
small batches, local validation, and only then push/deploy.

## Goals

- Preserve official WuWa CN PC CDN metadata without mirroring game binaries.
- Keep the static site fast by loading only a compact index at startup.
- Store large per-version file lists as lazy-loaded shards.
- Keep self-collected official launcher data and imported historical data from
  overwriting each other.
- Make every future data change reviewable, locally testable, and reversible.

## Current Data Layout

WuWa data lives under `docs/data/wuwa/`:

```text
docs/data/wuwa/
  index.json                 Compact game metadata and version summaries
  versions/
    3.4.1.json               One full version shard per version
    3.3.0.json
    ...
  lists/
    3.4.1-files.json         Download/browser file list
    3.4.1-files.urls.txt     Plain URL list
    3.4.1-files.aria2.txt    aria2 download helper
    3.4.0-patches.json       Optional combined patch-part list
    ...
```

`index.json` is intentionally small. It contains the game identity and a
summary row for each version: version, channel, region, file count, CDN count,
patch route count, sizes, source metadata, and last-modified metadata when
available.

The heavy data lives in `versions/{version}.json`. Each version shard contains:

- `version`, `channel`, `region`
- source fields such as `source`, `source_note`, `source_repo`, `source_commit`
- `resource_index`, `base_url`, `cdn_urls`
- `files`, where each file has `dest`, `name`, `md5`, `size`, `url`, `urls`
- `patches`, optionally with patch route entries and patch part lists
- `links`, pointing to generated JSON/URL/aria2 lists under `lists/`

## Source Types

There are two main source classes now:

| Source | Marker | Meaning |
| --- | --- | --- |
| Current/recovered official launcher indexes | `source: self-collected` | Generated by `scripts/sync_wuwa.py` from official launcher/resource-index URLs or recovered official resource-index URLs. |
| TomyJan historical import | `source: tomyjan-import` | Converted from TomyJan's public archive into local staging, then promoted into official site data after validation. |

This distinction matters because scheduled syncs must refresh current official
data without deleting imported historical shards.

## Sync Pipeline

`scripts/sync_wuwa.py` is the main generated-data script.

It does the following:

1. Reads launcher discovery metadata from the yuhkix `wuwa-downloader` metadata
   document.
2. Fetches the selected official launcher index for the requested channel and
   region.
3. Fetches the referenced official resource index.
4. Normalizes file entries into a stable shape:
   `dest`, `name`, `md5`, `size`, `url`, `urls`.
5. Writes per-version file list helpers with `write_named_lists()`.
6. Builds full version shards in `docs/data/wuwa/versions/`.
7. Builds compact summaries into `docs/data/wuwa/index.json`.
8. Adds known recovered historical official indexes and predownload indexes.
9. Reuses cached versions when a known upstream fetch fails and the cached
   linked list files still exist.
10. Preserves existing `source: tomyjan-import` shards if their linked list
    files still exist.

The important guard is this: imported historical shards are not regenerated by
the live launcher sync, so `sync_wuwa.py` explicitly loads cached shards and
adds TomyJan versions back into the final output.

## TomyJan Import Pipeline

The historical import is intentionally split into two scripts:

```bash
python scripts/import_tomyjan_wuwa.py
python scripts/import_tomyjan_wuwa.py --validate-only
python scripts/merge_tomyjan_wuwa_staging.py --batch 1.x
```

`scripts/import_tomyjan_wuwa.py`:

- clones or reads TomyJan's `GenshinImpact-Client-Version` repository
- reads `WW/Win/Game/CN/REL{version}.json`
- reads `WW/Win/Game/CN/REL{version}_Res.json`
- converts those into WuWa-shaped version shards
- writes only to `docs/data/wuwa/staging/`
- writes `_unconvertible.json` for missing or incompatible versions
- validates staging payloads before promotion

`scripts/merge_tomyjan_wuwa_staging.py`:

- promotes only an explicit batch
- refuses to overwrite an existing formal version shard
- generates list files for the promoted version
- refreshes `index.json`
- updates the expected total file count in `validate_wuwa_split.py`

The promotion batches used for the current import were:

- `1.x`
- `2.0-2.4`
- `2.5-2.7`
- `3.x`

This batch model is important. If a mistake appears, the bad change is confined
to one small commit instead of mixing every historical version into one large
diff.

## Frontend Loading Model

The frontend starts by fetching `./data/wuwa/index.json` together with the
other game indexes. It does not load all WuWa file entries at startup.

When a WuWa version is selected:

1. `loadWuwaVersion(version)` fetches
   `data/wuwa/versions/{version}.json`.
2. `loadWuwaEntries(version)` follows `row.links.files.json`.
3. `renderWuwaFiles()` renders the directory browser from that list.
4. Patch mode uses `version.patches` and optional patch list links.

This lazy loading is why switching versions may pause briefly: the browser is
fetching and parsing a full version shard and its file-list JSON for the first
time. After loading, `state.wuwaVersions`, `state.wuwaVersionPromises`, and
`state.wuwaEntries` cache the data in memory.

## Validation

The core validator is:

```bash
python scripts/validate_wuwa_split.py
```

It checks:

- `index.json` has no duplicate versions
- every index version has a matching shard
- no extra unindexed shard exists
- each shard has required version fields
- file counts match the summaries
- patch counts match the summaries
- every file has required fields
- declared `total_file_count` in `index.json` equals the aggregate shard total

After any WuWa-related change, also run:

```bash
node --check docs/app.js
python -m http.server 8765
```

Then open the local site and verify:

- all game entries still render
- Android / Arknights / WuWa / Hoyo / Endfield are still present
- a newly touched WuWa version loads its file browser
- no request falls back to the old aggregate `data/wuwa/versions.json`
- no console/page/request errors appear

## Common Failure Modes

### Imported Shards Disappear After Sync

Cause: a sync script rebuilds the version set from only current launcher data.

Mitigation: `sync_wuwa.py` preserves cached shards with
`source: tomyjan-import` when their linked list files exist.

### Index And Shards Drift Apart

Cause: manually adding/removing a shard without refreshing `index.json`, or
editing a summary count by hand.

Mitigation: always regenerate summaries from shards and run
`validate_wuwa_split.py`.

### Linked List Files Are Missing

Cause: deleting `docs/data/wuwa/lists/*` while keeping a version shard that
points to those files.

Mitigation: `cached_link_exists()` prevents preserving cached/imported payloads
whose `links` targets no longer exist. The validator and local UI checks should
also catch this.

### Large Frontend Payloads Slow Or Break Startup

Cause: moving all WuWa files back into a single eagerly loaded JSON file.

Mitigation: keep `index.json` compact and leave full file entries in lazy
loaded per-version shards and list files.

### File Browser Breaks Other Games

Cause: changing shared frontend state, shared render paths, or all-game loading
while working on WuWa.

Mitigation: WuWa-specific work should stay behind `isWuwa()` branches and must
be checked with all required game entries visible locally before commit.

### URL Encoding Differences

Cause: CDN paths can contain spaces, non-ASCII names, or already escaped
segments.

Mitigation: import scripts normalize URLs through `urlsplit`, `quote`, and
`urlunsplit` where needed. Do not hand-concatenate arbitrary raw paths unless
the source format is already known to be safe.

### Patch Routes Are Not Equivalent To Full Versions

Cause: treating patch resource indexes as full file lists.

Mitigation: keep patches under `patches` and separate `links.patches`; full
client files remain under `files` and `links.files`.

### Timestamp Churn Creates Noisy Diffs

Cause: sync scripts update `last_checked_at` or `generated_at` even when stable
content did not change.

Mitigation: before committing, inspect `git diff` and confirm whether the diff
contains real data changes. For future game pipelines, prefer stable comparison
helpers that preserve `generated_at` when content is unchanged.

## Safe Change Procedure

Use this checklist for WuWa and for future game pipelines modeled after it:

1. Start from a clean branch.
2. Make one kind of change only: importer, staging data, promotion batch,
   validator, or frontend support.
3. Generate to staging or a temporary output first.
4. Validate staging before touching formal data.
5. Promote one small batch.
6. Run local validation commands.
7. Run a local static server and verify all game entries.
8. Inspect the diff for unrelated files or unexpected deletions.
9. Commit that one step.
10. Push/deploy only after the local checks pass and the change scope is clear.

## Porting This Method To Other Games

Do not copy the WuWa data shape blindly. Copy the workflow:

- staging output
- explicit promotion
- source markers
- cache preservation rules
- structure validator
- local UI verification
- small commits

For Arknights PC, the first low-risk port should be:

1. add a validator for `docs/data/arknights/index.json`,
   `versions.json`, and `lists/`
2. make the sync write to staging or a temporary output
3. compare staged output with the current formal output
4. promote only if package counts, links, and required fields match
5. verify the local page still shows every game entry

That keeps the first experiment small while proving the same safety model can
work outside WuWa.
